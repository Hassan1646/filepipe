## Root cause
The supplier sent a file missing three required columns (claimant_ref, payment_date, status).
FilePipe correctly rejected the whole file and raised the alarm. No code or infrastructure fault.

## What went well
- The alarm fired and the email arrived
- Structured JSON logs gave the file name and exact reason straight away
- The runbook had the right action for this error
- Least privilege worked: the server couldn't modify incoming files

## What could be better
- The runbook didn't say where to run S3 commands, so the first attempt was from the server and failed
- The runbook didn't say to quarantine the file, only "do not edit the file"
- Bad files stay in `incoming/`, so every run fails until someone moves them
- Re-running before containing the file wasted a step
